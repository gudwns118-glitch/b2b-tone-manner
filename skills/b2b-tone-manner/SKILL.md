# B2B Tone & Manner

사용자가 직접 쓴 글을 정량 분석해 만든 문체 규칙이다. 목표는 "AI가 쓴 매끈한 글"이 아니라 **일 잘하는 실무자가 바로 써서 낸 글**이다.

| 모드 | 근거 | 규칙 파일 |
|---|---|---|
| **메일** | 1:1 메일 926통(2025-03~2026-11), 콜드 템플릿 16종 | `email/` |
| **문서** | Notion·Docs·Slides 30건(2022~2026) + 고객 제안 장표 2건 | `document/` |
| 사람·회사별 값 | 이름, 회사별 팀·서명·업무 어휘·회사 규칙 | 설치한 사람의 PC: `~/.claude/b2b-tone-manner/` (레포에는 빈 양식 `companies/_template`만) |
| 갱신 | 최근 글로 수치를 다시 재는 절차 | `update/` |

**우선순위**: 회사 profile의 "회사 규칙" > 모드 규칙. 모드 규칙(`email/`·`document/`)에는 문체만 있다. 상품·업종 명사, 숫자, 첨부 자료는 `{ }` 자리 표시로 비워 두었으니 현재 회사 profile이나 사용자가 준 사실로만 채운다. 이전 회사의 업종 어휘를 가져다 쓰지 않는다.

## 0. 사용자·회사 인식 (매번 먼저)

사람·회사별 값은 플러그인 폴더가 아니라 **사용자 폴더 `~/.claude/b2b-tone-manner/`**에 둔다(플러그인을 업데이트해도 남고, 레포에 개인 정보가 올라가지 않는다).

```
~/.claude/b2b-tone-manner/
  me.md                      {name}, {name_en}
  companies/<회사>/profile.md  회사별 값 (양식: 이 스킬의 companies/_template/profile.md)
```

1. **사람**: `~/.claude/b2b-tone-manner/me.md`를 읽는다. 없으면 이번 글은 `{name}`을 비워 두고 쓴 뒤, 끝에 "이름(한글·영문)을 알려 주시면 저장해 둘게요"라고 한 번 묻는다. 답을 받으면 아래 형식으로 만든다.
   ```
   | 변수 | 값 |
   |---|---|
   | `{name}` | {한글 이름} |
   | `{name_en}` | {영문 이름} |
   ```
2. **회사**: 사용자의 업무 메일 도메인을 확인한다(세션 컨텍스트의 사용자 이메일, 사용자가 말한 회사, 작업 중인 저장소·문서). `~/.claude/b2b-tone-manner/companies/*/profile.md` 맨 위 `domains`와 맞는 폴더를 현재 회사로 쓴다. 여러 개면 `period`가 열려 있는(끝 날짜 없는) 것.
   - 도메인을 알 수 없거나 개인 메일(gmail 등)뿐이면, `period`가 열려 있는 profile이 하나일 때 그 회사를 쓴다. 이직하면 이전 회사 profile의 `period`를 닫는다(`2025-03 ~ 2027-01`).
   - 사용자가 다른 회사를 말하면 그 말이 우선한다.
3. **맞는 회사가 없으면** (처음 설치했거나 이직했을 때):
   - 이번 글은 모드 규칙과 자리 표시로 쓴다. 이전 회사 profile은 열지 않는다(이전 회사 어휘가 섞이지 않게).
   - 자리 표시 기본값: `{company}`·`{team}`·`{service}`·`{subject_prefix}`는 그대로 비워 두고, `{title}`은 생략, `{고객 서명}`은 `{name} 드림.`으로 쓴다.
   - 끝에 한 줄 제안한다: "{도메인} 회사 프로필을 만들까요?" 승인하면 `companies/_template/profile.md`를 `~/.claude/b2b-tone-manner/companies/<회사 영문 slug>/profile.md`로 복사하고, 회사명·팀·직급·서명 관례만 물어 채운다. 업무 어휘·회사 규칙은 그 회사 글이 쌓인 뒤 `update/UPDATE.md`로 채운다.
4. 현재 회사 profile의 `last_updated`가 `update_every_days`보다 오래됐으면 작업을 끝낸 뒤 한 줄만 덧붙인다: "말투 규칙을 마지막으로 갱신한 지 {N}일 지났습니다. 최근 글로 업데이트할까요?" 같은 대화에서 두 번 묻지 않는다.

## 1. 모드 판정

| 요청 | 모드 |
|---|---|
| **메일 및 전자 서면 커뮤니케이션**: 메일·회신·답장·콜드메일·팔로업, 공문 회신, 고객 안내 메시지, 카톡·문자·슬랙 | **메일** |
| 제안서·서비스 소개서 장표 | **문서** (`document/types.md` §0) |
| 기획안·회의자료·협의(안)·보고·슬라이드·포트폴리오·회고·상세페이지·작업 요청서·노션 페이지 | **문서** |
| 기관·거래처에 돌릴 협조 공문 원고 | **문서** (`document/types.md` §7) |
| 메일 본문에 첨부할 제안서 요약 | 메일 본문은 메일, 첨부 문서는 문서 |

애매하면 결과물이 **받는 사람에게 바로 가는 글**이면 메일, **저장·공유되는 자료**면 문서다. 두 모드는 연결어부터 다르다(메일은 "추가로·다만", 문서는 "이에·이를 통해·또한"). 섞지 않는다. 예외: 제안 장표의 견적 장 안내 문장("편하게 말씀 부탁 드리겠습니다")은 메일 말투 그대로 쓴다(`document/types.md` §0).

**상황 뼈대는 영업·고객 담당 업무에서 나왔다**(견적·계약·팔로업·협상·수주 위주). 뼈대에 없는 상황(장애 공지, 릴리스 안내, 내부 승인 요청 등)은 가장 가까운 뼈대와 말투 규칙(어미·연결어·띄어쓰기·기호)으로 쓰고, 그 상황의 업계 관행을 지어내지 않는다. 말투 규칙은 업종·직무와 무관하게 그대로 적용한다.

## 2. 읽는 순서

1. `~/.claude/b2b-tone-manner/me.md` → `~/.claude/b2b-tone-manner/companies/<현재 회사>/profile.md` — 모든 출력의 고정값
2. 메일 모드: `email/voice.md` → `email/anti-patterns.md` → 상황별 `email/situations.md` 또는 콜드·대량이면 `email/cold-outreach.md`
3. 문서 모드: `document/voice.md` → `document/types.md`의 해당 유형 → `document/anti-patterns.md`
4. "말투 업데이트" 요청이면 `update/UPDATE.md`만 따른다.

## 3. 두 모드 공통 원칙

1. **수식어 대신 숫자·날짜·조건.** 혁신적인·최적의·소중한·완벽한·극대화 같은 과장은 쓰지 않는다.
2. **모르는 값은 지어내지 않는다.** 이름·직급·금액·날짜·수치는 `{이름}`, `{금액}`처럼 비운다.
3. **주어진 사실에 없는 약속·제안·성과를 덧붙이지 않는다.**
4. **엠대시(—)를 쓰지 않는다.** 메일은 "~며"로 잇고, 문서는 `→`·`:`·괄호를 쓴다.
5. **"따라서·즉·결과적으로·무엇보다·주저하지 마시고·하시기 바랍니다"는 어느 모드에도 없다.**
6. **띄어쓰기 습관**: "전달 드립니다 / 부탁 드리겠습니다"는 띄우고 "감사드립니다"는 붙인다(메일). 문서에서는 "셋팅".
7. **날짜·금액**: `11/25(화)`, `2026.07.15.(수)`, `30,000원(vat별도)`, 증감은 `A → B`, 비교는 `比`.

## 4. 작업 절차

### 작성 (내용을 받아 새로 쓸 때)
1. 모드와 유형을 정한다. 메일이면 수신자 유형(고객/기관/파트너/벤더/개인 협력자/내부/영어)과 상황, 문서면 문서 종류와 독자(내부/고객/공공/공개).
2. 해당 뼈대(`email/situations.md`, `document/types.md`)로 초안을 쓴다. 회사 profile의 "회사 규칙"에 같은 상황이 있으면 그것을 따른다.
3. 모드의 `anti-patterns.md` 끝 체크리스트로 자기검수하고 고친 뒤 낸다.

### 교정 (AI나 다른 사람이 쓴 초안을 받았을 때)
1. **내용은 건드리지 않는다.** 사실·숫자·약속·첨부 언급은 그대로 두고 순서·문장·표현만 바꾼다.
2. 모드의 대조표 패턴을 찾아 바꾼다.
3. 모드의 뼈대로 재배치한다.
4. 체크리스트를 돌린다.
5. 요청받았을 때만 바꾼 점을 2~3줄로 알린다.

## 5. 출력 규칙

- 결과물부터 바로 낸다. 해설이 필요하면 뒤에 짧게 붙인다.
- 메신저(Slack·카톡·문자)는 메일 모드에서 인사·소속·서명 뼈대를 빼고 어휘·문장 규칙만 쓴다.
- 영어 메일은 `email/voice.md` §6 영어 규칙을 따른다. 한국어 규칙을 번역해서 쓰지 않는다.
- 문서 모드에서 Notion·Docs에 직접 쓰는 것은 사용자가 요청했을 때만 한다. 기본은 대화에 결과물을 낸다.
