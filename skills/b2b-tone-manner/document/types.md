# Document Types — 문서 유형별 뼈대

모르는 값은 `{ }`로 비운다. 회사 고유 명사는 현재 회사 profile에서 가져온다.

## 0. 제안서·서비스 소개서 (고객 제안 장표)

근거: 본인이 직접 쓴 고객 제안 장표 2건(공공기관 대상, 13~18장). 회사 공용 장표(도입 사례, 카테고리, 상품 소개)는 근거에서 뺐다. 표본이 적어 비율은 쓰지 않고 구조와 표현만 둔다.

```
[표지]    {고객사} 제안서
          (한 줄 훅) "~한 {company}. {company}에서 ~을 시작하세요!"
[소개]    헤드라인 + 핵심 수치 3개 + *출처 각주
[차별점]  장마다 오른쪽 위 위치 표시 `첫번째 차별점 - {키워드}`
          큰 헤드라인 1줄 (합니다체 선언 또는 명사구)
          보조 1~2줄 → 숫자·화면·사례
[제안]    "{고객사} {대상}의 {목적}을 위한 N가지 서비스를 제안 드립니다."
          고객 입장 말풍선("~하고 싶어요!") → 서비스명 → 비교표
[사례]    고객 담당자 인터뷰 Q&A (질문은 굵게, 답은 고객 말투 그대로)
[견적]    "정가 기준 최대 {n}%의 할인율로 제안 드립니다."
          "내부 예산 검토 간 추가 협의가 필요하시다면 편하게 말씀 부탁 드리겠습니다."
          ※ 하기 단가 제안은 예시이며 협의에 따라 변경될 수 있습니다.
          | 구분 | 상세 | … |  →  `총 서비스 비용 : {금액}원`
[마무리]  "도입 이후 운영까지, {company} {team}이 함께 합니다."
          "{고객사}을 위한 ~을 시작해 보세요!" + 문의처
```

- **종결을 섞는 게 이 매체의 문체다.** 장 제목·선언은 합니다체("~플랫폼입니다.", "~보유하고 있습니다."), 혜택 설명 한 줄은 해요체("~달성할 수 있어요", "~지원해드려요", "~기업에 적합해요!"), 서비스 라벨은 명사구("{효과} 형성!", "{효과} 달성!"). "~하였습니다"는 쓰지 않는다.
- 느낌표를 쓴다(장당 0~2개). 표지 훅, 서비스 라벨, 마지막 장.
- **고객사 이름을 표지·제안·사례·마지막 장에 넣는다.** 같은 장표를 돌려 쓰더라도 제안 장은 고객별로 새로 쓴다.
- 고객 입장 문장(말풍선)과 인터뷰 답변은 고객의 구어체를 그대로 둔다. 이 부분은 교정하지 않는다.
- 수치는 큰 숫자 + 짧은 라벨(`{N}만 명 / 함께하는 {이용자}`), 출처 각주는 자사 데이터면 `*{company} 내부 데이터, {기준 시점}, {표본}`, 외부 조사면 `*출처: {조사기관} {YY년 M월} … {n}명 대상`.
- 사실이 없는 장(사례 인터뷰, 고객 말풍선)은 지어내지 않고 뺀다. 핵심 수치도 있는 만큼만 쓴다.
- 비교는 `VS`, 조건 단서는 `※`, 카테고리 나열은 `·`.
- "제안 드립니다 / 부탁 드리겠습니다"는 메일처럼 띄어 쓴다.

## 1. 포트폴리오·프로젝트 회고 (Notion 서술형)

```
기간: YYYY.MM ~ YYYY.MM
설명: (합니다체 2~3문장 요약)
> 기여도 ★★★★☆
> 주요 업무 #제안 #기획 #운영 #정산

**📈주요 성과**
| 항목 | Before | After | 증감률 |

**📌추진 배경**     규제·시장·내부 문제 → "~필요한 상황이었습니다"
**🔎가설 설정**     "~라 판단하였습니다 / ~라는 가설을 세웠습니다"
**📝협업 제안 / 사업 구조 설계**
**🤝획득 성과**     수치 + 기준
**📝운영 전략 수립**
**⚠문제 발생**
**✨개선 및 학습**   "~을 학습할 수 있었습니다"
```

- 헤더는 **이모지 1개 + 굵은 명사구**, 이모지 뒤에 띄어쓰기 없음. `###` 마크다운 헤딩보다 굵은 글씨 헤더가 기본.
- **섹션 본문은 줄글 문단이 아니라 `-` 불릿이다.** 상위 불릿은 합니다체 한 문장("~하였습니다."), 하위 불릿은 그 근거를 개조식 조각으로 단다.
  ```
  - CRM 툴 **{도구}**를 활용하여 끊김 없는 리드 응대 프로세스를 구축, 영업 기회를 지속 발굴하였습니다.
    - 유입 채널 별 필드값 자동 매핑 워크플로우 셋팅 및 맞춤 응대 진행
    - {단계} → {단계} → {단계} → {단계}로 이어지는 체계적인 프로세스 구축
  ```
- 주요 성과 표는 성과 영역을 열로 둔 한 줄 요약표(`전환율 | 매출 | 운영 효율`)여도 된다. 세부 수치는 🤝획득 성과의 하위 불릿에 `A → B (n배 개선, +n%p)`로 쓴다.
- **실패·학습 섹션을 빼지 않는다.** 성과만 나열하면 본인 글이 아니다.

## 2. 고객 회의자료·협의(안)

제목: `[회의자료] {사업명} 「{프로그램명}」 {무엇} 구축 및 기능 협의(안)`

```
# 1. 개요 및 사업 방향
- 협력 히스토리 : …
- 핵심 목표 : …
# 2. {company} 소개 및 경쟁력
# 3. 서비스 제공 방식
# 4. 기능 요구사항 협의
1) {기능}
  ① …
  - 우리 기본안 : "~을 상정하고 개발하려고합니다"
  - 결정 필요 : "어떤 방향을 선호하시나요?" / "~논의가 필요합니다"
```

- 순서는 교과서형(배경-목표-방안-기대효과)이 아니라 **현황 → 우리가 할 것 → 협의할 것**.
- 상대가 정해야 할 것은 개조식 사이에 **질문으로** 둔다. 질문 앞에는 선택지와 그 영향을 적는다: "{기능}의 목적이 '{목적 A}'인지 '{목적 B}'인지에 따라 {옵션}({안 1} vs {안 2})이 달라집니다. 어떤 방향을 선호하시나요?"
- 사전 질의서는 의문 명사절에 물음표: "{대상}의 최소 {기준} 규정이 있는가?" → 답은 `-> *과거 유선통화 시, ~라고 함.*`

## 3. 기획안·화면 기획 (공공·고객 공유용 포함)

- 제목 꼬리: `(안)`, `({고객} 공유용)`, `(내부용)`, 버전 날짜 `_YYMMDD`.
- 외부 공유용이어도 **개조식**. 사용자에게 보이는 안내·경고 문구만 합니다체("~할 수 있습니다 / ~진행됩니다").
- 단서는 `※`: "※ 삭제조치된 계정에 대한 {이용 이력}은 목표 실적 및 청구 데이터에 포함되지 않음"

## 4. 슬라이드 (보고·타운홀·제안)

- 장 제목: `{번호}. {영역} · {세부}` 또는 `# 진척 - {항목}`.
- 각 장 = **한 줄 결론 헤드라인 + 보조 한 줄** → 근거 표/불릿.
- 문제→해결은 한 줄에 `→`: "{협력자} 계약에 {필요 조항} 부재 → 부속합의서 체결".
- 마지막 장은 다음 행동: `다음 단계`, `관심을 둬야 할 영역`.

## 5. 현황 보고 (내부·고객·공공)

- 항목별 `라벨 : 상태` 한 줄: "발표자료 취합 현황 : 사업소개 자료 취합 완료, 강연자료는 6월 11일까지 취합 예정".
- 숫자와 마감일을 같이 쓴다. 감정·평가어 없이 상태만.

## 6. 내부 작업 요청·콘텐츠 기획

상단 메타 블록:
```
- 대상 :
- 발송일정 :
- 발송목적 :
- 콘텐츠 기획 의도 :
```
요청 사항은 `- 하지 말 것 X → 대신 할 것` 한 줄: "- 카드, 돈 이미지 활용 X → 사업 관련 아이콘으로 활용 요망".

## 7. 외부 협조 공문 (기관·거래처에 보내는 안내 원고)

메일이지만 문서 원고로 미리 쓰는 경우. 메일 모드보다 격식이 높다.
```
안녕하세요, {기관} {담당} 담당자님.
{company} {team}입니다.

(배경 한두 문장, 합니다체)
~ 안내해 드오니, {요청} 협조를 정중히 부탁드립니다.

- {라벨} : {값}   (개요 불릿)

관련하여 문의 사항이 있으시거나 추가 자료가 필요하신 경우 언제든 편하게 연락 주시기 바랍니다.
감사합니다.
```

## 8. B2C 모집 카피·신청자 안내

- 유일하게 해요체·느낌표·✔ 체크를 허용한다.
- 그래도 과장 수사(§anti-patterns)는 쓰지 않는다. 혜택은 숫자로: "{비용 항목} 전액(100%) 지원".
